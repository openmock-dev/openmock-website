Schema for an OpenMock document — an open format for defining API mocks in a single YAML file. A document declares a list of named, type-tagged servers, each carrying its own operations. Validates the envelope strictly while allowing arbitrary YAML bodies and messages.

This viewer documents the OpenMock JSON Schema (draft 2020-12). It validates the document envelope strictly — servers, operations, scenarios, matching, and responses — while allowing arbitrary structured bodies and messages. Download the raw schema.

The document

The root object. additionalProperties is false — only the fields below (and x- extensions) are allowed.

OpenMock documentobject

openmock string required

The OpenMock format version this document targets (SemVer).

pattern ^\d+\.\d+\.\d+$
info info optional
servers array<object> required

The mock servers this document describes. Each server is named, carries one protocol type, and holds its own operations; a document may declare several servers of the same type.

minItems 1
x-*anyextension

Specification extension. Any property whose name starts with x- is allowed and ignored by validation.

Metadata

infoobject

Human-oriented, non-normative metadata.

title string optional
version string optional
description string optional

serverNamestring

The server's name: how normalized requests address it. Unique across the servers list (a spec-level load-time rule).

See type above.

serverPortinteger

Optional default port hint for implementations serving this server over a network. A hint only: it never affects routing, matching, or rendering, and engines MAY override it. See docs/serving.md.

min 1max 65535

Request matching (when)

httpWhenobject

Condition under which an HTTP scenario applies. All declared facets must match. Omitting when makes the scenario the default fallback.

params matcherMap optional
query queryMatcherMap optional
headers matcherMap optional
body payloadMatcher optional
calls callsMatcher optional

grpcWhenobject

Condition under which a gRPC scenario applies. All declared facets must match. Omitting when makes the scenario the default fallback.

metadata matcherMap optional
message payloadMatcher optional
calls callsMatcher optional

graphqlWhenobject

Condition under which a GraphQL scenario applies. All declared facets must match. Omitting when makes the scenario the default fallback.

variables matcherMap optional
headers matcherMap optional
calls callsMatcher optional

websocketWhenobject

Condition under which a WebSocket scenario applies. params/query/headers match the connection-scoped values fixed at establishment; message matches the individual inbound message. All declared facets must match. Omitting when makes the scenario the default fallback.

params matcherMap optional
query queryMatcherMap optional
headers matcherMap optional
message payloadMatcher optional
calls callsMatcher optional

callsMatcherobject

Matches the operation's call counter: an exact positive integer, or an object with inclusive min/max bounds (at least one required). `n` is shorthand for {min: n, max: n}.

A discriminated shape resolved to one of: see below.

Matchers & helpers

stringMapobject

A map of string keys to string values.

*stringmap value

Additional properties (map entries) of the type above.

existsMatcherobject

Presence matcher: true asserts the target is present (any value), false asserts it is absent.

exists boolean required

patternMatcherobject

Pattern matcher: an RE2 pattern matched against the target's entire canonical string form (implicitly anchored). A pattern that is not valid RE2 makes the document invalid.

pattern string required

valueMatcherobject

A discriminated shape resolved to one of: existsMatcher, patternMatcher.

matcherMapobject

A when-facet map: each value is a string (exact match on canonical string form) or a matcher object ({exists: bool} | {pattern: RE2}). At least one key — an empty facet map is not a constraint.

*string | valueMatchermap value

Additional properties (map entries) of the type above.

payloadMatcherobject

body/message facet: a map of dotted paths to strings or matcher objects, or a single string matching the whole payload by its canonical string form.

A discriminated shape resolved to one of: matcherMap.

queryMatcherMapobject

Query facet: each value is a non-empty list matched against the parameter's full occurrence sequence exactly — same order, same count; elements are strings or pattern matchers. Alternatively an exists matcher asserts the parameter's presence or absence. There is no string form. At least one key — an empty facet map is not a constraint.

*array<string | patternMatcher> | existsMatchermap value

Additional properties (map entries) of the type above.

headerMapobject

Response headers: each value is a string, or a non-empty list of strings emitted as one field line per item, in order (for headers that cannot be comma-joined, like Set-Cookie).

*string | array<string>map value

Additional properties (map entries) of the type above.
